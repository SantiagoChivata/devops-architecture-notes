# DevOps Architecture Notes

> Software architecture notes, C4 diagrams, and Architecture Decision Records (ADRs) — written from a DevOps engineer's point of view, based on real-world microservices systems.

## Why this repo?

I'm a DevOps engineer, not a software architect. But every day I deploy, scale, and troubleshoot distributed systems — and I've learned that understanding *why* a system is designed a certain way makes me far better at my job.

This repo is my structured effort to close that gap: documenting architecture patterns I work with, diagramming real systems (anonymized), and recording the trade-offs behind key decisions.

## What's inside

| Section | Description |
|---------|-------------|
| `/diagrams` | C4 model diagrams (Context & Container level) of real microservices architectures |
| `/adr` | Architecture Decision Records — the reasoning behind key design choices |
| `/notes` | Concept notes: patterns, trade-offs, and how they map to real incidents |

## Topics covered

- Monolith vs. microservices trade-offs
- Service discovery, API Gateway, Circuit Breaker patterns
- The C4 model for communicating architecture
- Networking fundamentals for distributed systems
